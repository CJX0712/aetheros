# ADR-014: 图标清单机器校验与 CI 门禁

## Status: Accepted (2026-09-19)

## Background

图标库由 Lucide 改判为 Tabler（ADR-006）后，设计侧产出的 40+ 条语义映射表仍是 Lucide 键名。需要重键为 Tabler。

**关键风险**：凭记忆把 Lucide 名翻成 Tabler 名，极易产出"看着合理、实际不存在"的图标名。这类错误**编译期未必报错，运行时渲染成空白**，要到验收才暴露，且 40+ 条逐一人工核对既慢又不可靠。

这是典型的可预判失效模式，应当用机器门禁防住，而不是靠人眼审表。

## Decision

**不手工翻译图标名。改为「单一真源 + 构建期解析 + CI 门禁」。**

### 1. 单一真源
`packages/ui/src/icons.manifest.ts`，一个语义槽一条：

```ts
export const ICON_MANIFEST = [
  { slot: 'nav.overview',      icon: 'IconLayoutDashboard', filled: 'IconLayoutDashboardFilled' },
  { slot: 'runtime.abort',     icon: 'IconPlayerStop',      filled: null },
  { slot: 'status.verified',   icon: 'IconCircleCheck',     filled: 'IconCircleCheckFilled' },
  // …
] as const;
```

`filled: null` 表示该语义槽**没有 filled 孪生** —— 该字段同时承担 ADR-006 中"filled 覆盖率仅约 20%"的兜底标记职责。

### 2. 构建期解析
构建脚本安装 `@tabler/icons`（原始 SVG + 元数据）作为**构建期依赖**，读取其元数据，逐条解析 manifest 中的图标名。

### 3. CI 门禁
任一图标名解析失败 → **构建红灯**，阻止合并。

### 4. 单一 manifest 供两位设计师共同引用
取消"两位设计师各出一份映射表"的做法——两份表必然打架。设计侧按 manifest 格式交付，架构侧落库。

## 已知高危项（需设计侧在 tabler.io/icons 现场确认）

以下为 Lucide 特有命名或两库词序不一致者，**命中率最低，不得凭记忆填写**：

- `Trash2` / `Settings2` / `Maximize2` —— Tabler 无 `-2` 后缀体系
- `RefreshCw` —— `Cw` 是 Lucide 命名
- `MemoryStick` / `FlaskConical` / `GitCommitHorizontal` / `BadgeCheck` —— Tabler 未必有同名
- `Ellipsis` —— Tabler 用 `dots` 体系
- `Play` / `Pause` / `Square` —— Tabler 媒体图标走 `player-` 前缀；**中止建议改用 `IconPlayerStop`（语义比 `Square` 准）**
- `ArrowUpDown` —— Tabler 方向类常带 `arrows-` 前缀
- `TriangleAlert` / `CircleAlert` / `Info` —— Tabler 告警类走 `alert-` 前缀，**词序与 Lucide 相反**，极易写反
- `CheckCheck` —— Tabler 可能是 `IconChecks`

## Consequences

**正面**
- 图标名错误在 CI 即红，不流入运行时
- 单一真源消除两份映射表打架
- `filled` 字段显式暴露覆盖率缺口，迫使设计侧定兜底规则

**负面**
- 需维护构建脚本（约 50 行）
- `@tabler/icons` 作为构建期依赖，仓库体积增加（该包含全部原始 SVG）

## 关联硬约束

- 图标名**禁止手工翻译**，一律经脚本解析
- `brain` / `sparkles` 及同类 AI 模板味图标写入 lint 禁用词（ADR-006）
