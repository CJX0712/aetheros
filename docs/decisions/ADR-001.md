# ADR-001: 运行时与语言选型

## Status: Accepted (2026-09-19)

## Background

aetheros 是本地优先的智能体运行时，需要在用户本机直接安装运行。运行时选择决定了三件事：原生 addon（better-sqlite3、llama.cpp 绑定）能否稳定加载、MCP 官方 SDK 能否使用、以及用户安装门槛。

候选：
- Node.js ≥ 22.19.0（已转 Maintenance LTS，EOL 2027-04-30）
- Node.js 24（Active LTS，支持至 2028-04-30）
- Bun 1.x

语言候选：
- TypeScript 6.0.3（2026-03-23，最后一个基于 JS 代码库的稳定版）
- TypeScript 7.0（2026-07-08 GA，Go 原生重写，宣称约 10× 提速）
- JSDoc + checkJs

## Decision

**运行时：Node.js，最低支持线 `>= 22.19.0`；CI 增加 24 的矩阵验证；README 声明 24 为推荐开发环境。**

- MCP 官方 SDK v2 配套的 inspector v2 强制 `engines.node >= 22.19.0`
- pnpm 11 为纯 ESM 分发，要求 Node 22+
- 用户明确要求 Node 22，最低线不动；但 22 已非 Active LTS，故 README 引导新用户上 24

**语言：TypeScript 6.0.3，精确版本，不用 `^`。**

- TS 7.0 虽已 GA，但生态（类型定义、插件、构建链路）尚未稳定，且 6.0 是官方定位的"通往 7.0 的桥接版"
- `strict: true` 已是 6.0 默认；`target` / `module` / `lib` 必须在 tsconfig 显式写出，不依赖默认值
- MCP SDK v2 文档明确提示：TypeScript ≥ 6.0 不再自动包含 `@types/*`，必须 `compilerOptions.types = ["node"]`

## Consequences

**正面**
- 原生 addon 生态最完整，better-sqlite3 与 node-llama-cpp 均有预编译二进制
- MCP 官方 SDK 直接可用，无需 shim
- TS 6.0.3 是生态兼容性最高的稳定点

**负面**
- Node 22 仅剩安全修复，2027-04-30 EOL，届时需引导用户迁移
- 放弃 TS 7.0 的约 10× 类型检查提速

**观察项**：TS 7.0（`tsgo`）稳定度、Node 24 生态适配情况，Q4 复评。
