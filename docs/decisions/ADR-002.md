# ADR-002: 本地推理后端选型

## Status: Accepted (2026-09-19)

## Background

产品承诺"不需要 API key，不需要 GPU"，7B 级模型必须在纯 CPU 本机跑起来。同时 glassbox 的 rerank 与 aurora 的 nomic-embed 都要求后端同时支持 **LLM 生成、embedding、reranking** 三类能力。

SPEC §3 明确"禁止自研推理引擎——复用 llama.cpp / Ollama / transformers.js，差异在默认值不在 kernel"。

候选（版本经联网核实，2026-09-18）：
- **node-llama-cpp 3.20.0**（2026-08-12，socket.dev）
- Ollama 0.34.1（2026-09-14）
- transformers.js 4.2.0（2026-04-22）

## Decision

**选定 node-llama-cpp 3.20.0 作为主后端；Ollama 作为可选 provider，置于 `@aetheros/aurora` 的 provider 接口之后，不作硬依赖。**

选择理由：
1. **进程内加载**，无需外部守护进程 —— 直接决定"安装即用"能否成立
2. 预编译二进制覆盖 macOS / Linux / Windows（含 win-arm64），无 node-gyp / Python 依赖
3. 原生支持 **embedding 与 reranking**，与 glassbox 的三路检索信号一一对应，无需再引入第二个库
4. 内置 JSON schema grammar 与 function calling，可用于 ReAct 工具调用的结构化约束
5. 完整 TypeScript 类型

出局理由：
- **Ollama**：需用户额外安装并常驻守护进程，违背"零安装即用"；但保留为 provider，供已装 Ollama 的用户复用其模型库
- **transformers.js**：不支持 GGUF 格式，且 CPU 上跑 7B 不可行 —— 它是浏览器/小模型方案，不是本机 7B 方案

## Consequences

**正面**
- 单一依赖覆盖 LLM / embedding / rerank 三类能力
- 无外部进程，AC-01 零出站更容易证成
- 预编译二进制省去用户侧编译

**负面**
- 包体积大（安装尺寸约 32 MB，含二进制约 777 MB）
- 同步 API 会阻塞主线程，必须隔离到 `worker_threads`（见 ADR-008 分层约束）
- 绑定 llama.cpp 上游节奏，升级需回归

## 关联硬约束

- **线程数**：`autoThreads()` 夹到 [2, 4]（AC-02 / AC-03）。实测 4 线程 32.5 tok/s vs 16 线程 8.2 tok/s——小量化模型瓶颈在内存带宽不在算力
- **内存**：7B Q4_K_M 权重 4.68 GB（bartowski 实测），硬底线 8 GB 空闲内存，推荐 16 GB
- **不可同驻**：7B 与 embedding 模型不可在 8 GB 机同驻，需 `@aetheros/aurora` 做 LRU 生命周期管理
- **Qwen3 禁发 `think: false`** —— 该参数不减少思考，只是把推理从 `thinking` 倒进 `content`
