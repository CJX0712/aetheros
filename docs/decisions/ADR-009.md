# ADR-009: 包管理、构建与发布

## Status: Accepted (2026-09-19)

## Background

多包工程（10 个 `@aetheros/*` 包）需要 workspace 管理、构建与 npm 发布。同时 AC-01 要求"零出站请求"可被机检，这依赖依赖供应链的整洁度。

候选：
- **pnpm 11.22.0**（2026-08-15，eol.wiki）
- npm workspaces
- Bun

## Decision

**包管理：pnpm 11.22.0，workspace monorepo。**
**构建：tsdown（Rolldown）。**
**发布：npm，开启 provenance（`npm publish --provenance`）。**
**CI：GitHub Actions。**

Actions 版本（Node 20 actions 已于 2026-06-02 到期，必须用 v6 系列）：
- `actions/checkout@v6`
- `actions/setup-node@v6`
- `pnpm/action-setup@v6`（v4 无法正确处理 pnpm 11 的纯 ESM 分发）

pnpm 11 注意事项：
- **纯 ESM**，要求 Node 22+
- 不再读取 `package.json` 的 `pnpm` 字段，安全覆盖需改写入 `pnpm-workspace.yaml`
- `strictDepBuilds` 默认为 `true`；依赖 install / postinstall 脚本的包需显式 `allowBuilds`（node-llama-cpp、better-sqlite3 属此类）
- `minimumReleaseAge` 默认 1440 分钟（1 天），属供应链卫生默认，保留

## Consequences

**正面**
- pnpm 严格依赖解析：未声明的依赖直接报错，防止幽灵依赖
- `minimumReleaseAge` 默认 1 天，天然阻挡刚发布即被投毒的包
- provenance 让使用者可验证产物确实来自 GitHub CI

**负面**
- pnpm 11 纯 ESM + `strictDepBuilds` 会带来一次性迁移/配置成本
- tsdown 尚未 1.0，存在 breaking 风险 → pin 版本

## 关联硬约束

- **版本硬锚写入 `package.json` 精确版本**，关键件禁止 `^` 漂移（清单见 `docs/architecture/ARCHITECTURE.md` §10）
- **出站请求计数**：`outboundCount` 写入每一条 trace，默认 0，随审计包导出
- **单一 `net` 模块**：`packages/core/src/infra/net.ts` 是全项目唯一允许发起 HTTP 的位置。`fetch` / `node:http` / `node:https` / `undici` 在 ESLint 中全局禁用，仅该文件白名单放行。任何模块自行发起请求 = 计数器失效 = AC-01 不可机检

### 出站口径定义
`出站 = 非回环地址`（非 `127.0.0.0/8`、`::1`、`localhost`）。回环调用单独记为 `loopbackCount`，不计入出站——数据未离开本机。
