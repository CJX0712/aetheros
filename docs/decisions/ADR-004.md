# ADR-004: 可观测方案（OTel + 本地 SQLite Exporter）

## Status: Accepted (2026-09-19)

## Background

AC-09 要求"可完整重建输入 / 检索 chunk / 工具调用序列 / LLM 原文 / 最终输出"，AC-10 要求防篡改，AC-11 要求配置 OTLP 端点时 emit 符合 GenAI semconv 的 span。

SPEC §3 明确"禁止自研可观测后端 / 仪表盘 UI——只 emit OTel GenAI semconv，由 Grafana / Tempo / Datadog 渲染"。

候选：
- **OpenTelemetry JS SDK**（`@opentelemetry/sdk-node` 0.219.0 / `api` 1.9.0）
- 自研 trace 库
- Pino + 自研 span

## Decision

**采用 OpenTelemetry JS SDK，并自研 `SQLiteSpanExporter` 实现 `SpanExporter` 接口落本地 SQLite。**

- OTel 已于 2026-05-21 达 CNCF **Graduated** 状态（与 Kubernetes、Prometheus 同级），三个信号（traces / metrics / logs）在各语言 SDK 均已稳定
- 只 emit，不自研后端：配置 OTLP 端点时额外导出到第三方 collector；未配置时仅落本地

`SQLiteSpanExporter` 必须实现两个方法：
```
export(spans: ReadableSpan[], resultCallback: (result: ExportResult) => void): void
shutdown(): Promise<void>
```

## Consequences

**正面**
- 语义约定标准化：第三方 collector 无需适配即可消费
- trace context 自动传播，日志与 span 天然关联
- 导出目标可切换：本地 SQLite ↔ OTLP，应用代码零改动

**负面**
- `@opentelemetry/sdk-node` 仍在 0.x 实验版本轨道，版本间可能有破坏性变更 → **精确 pin `0.219.0`**
- 需自研 exporter（约 100 行），但这不是"重造轮子"，而是标准接口的本地实现

## 关联硬约束（内嵌坑）

- **GenAI semconv 截至 1.40 仍为 Development 状态** → 实现必须 pin 版本
- **新旧字段名并存**：同时发送 `gen_ai.provider.name`（新）与 `gen_ai.system`（旧），部分 collector 仍读旧字段
- **不存在 `gen_ai.usage.cost` 字段** —— 成本必须自行推导，不得假设该字段存在
- **批量写盘**：512 条 / 5s，禁止逐 span 同步 insert
- **出站计数写入每一条 trace**（见 ADR-009 / AC-01）
