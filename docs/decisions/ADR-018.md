# ADR-018: 门禁脚本可信性修复（图标族分离 + 离线守卫拦截点）

## Status: Accepted (2026-09-19)

## Background

首次真实执行 `pnpm verify` 时，两条门禁脚本自身暴露正确性缺陷。门禁的价值全部建立在「它的红灯可信、绿灯也可信」之上——一个会误报或会崩溃的门禁比没有门禁更危险。以下两条都必须修到有机械证据为止。

### 缺陷一：`check-icons.mjs` 索引被 filled 族污染（ADR-014 的落地漏洞）

`@tabler/icons` 3.46.0 的实际布局（实测）：

```
icons/outline/*.svg   5130 枚，带 stroke-width="2"
icons/filled/*.svg    1054 枚，与 outline **同名同 basename**，用 fill 而非 stroke
```

两个后果：

1. **几何校验会误判**。原实现用 `index.set(basename, path)` 单表索引，filled 族后遍历、覆盖 outline 条目。1054 枚 filled 图标全部都有 outline 同名孪生，被覆盖后 `readFileSync` 读到的是 filled 文件——而 filled 文件**没有** `stroke-width="2"`，于是所有有孪生的图标都会在几何校验处假红。
2. **filled 孪生判定永远为假**。原实现检查 `icons.has(name + '-filled')`，但本包 filled 文件叫 `icons/filled/<name>.svg`，从不叫 `<name>-filled.svg`（那是 `@tabler/icons-react` 的**导出**命名，不是文件命名）。于是 `[WARN] 无 filled 孪生` 会无条件打印，告警失去意义。

### 缺陷二：`offline-guard.mjs` 直接崩溃（AC-01 的守卫自身不工作）

原实现 `const net = await import('node:net')` 后执行 `net.connect = guardedConnect`，抛：

```
TypeError: Cannot assign to read only property 'connect' of object '[object Module]'
```

ESM 模块命名空间对象是**只读**的。守卫一安装就崩，`test:offline` 整条链路无法执行——也就是说 AC-01「零出站」在首次真跑之前**从未被真正验证过**。

进一步的实测（node 22）还发现一个更隐蔽的问题：即使换成可写对象，**只补导出对象也拦不住 ESM 消费者**——

| 补丁位置 | 能否拦到 |
|---|---|
| `net.connect`（CJS 导出对象） | 只拦 `require('node:net').connect`；`import { connect }` 在链接期已固化原函数，拦不到（实测 `netEsm.connect === 原始 cjs connect` 为 true） |
| `net.Socket.prototype.connect` | **同时**拦到 `net.connect`(CJS) / `net.connect`(ESM) / `createConnection` / `tls.connect` / `http.get` / `https.get`（6/7） |
| `globalThis.fetch` | undici 不走 `Socket.prototype`，必须单独补 |

## Decision

### 一、`check-icons.mjs`：按族分离索引

1. 索引拆成 `outline` / `filled` 两张表；族判定同时兼容两种布局——路径含名为 `filled` 的目录段，或文件名以 `-filled` 结尾（保持对目录布局不做硬假设）
2. **图标名只允许在 outline 族解析**，`name` 必须指向描边图标；几何校验（`viewBox 0 0 24 24` + `stroke-width="2"`）只在 outline 文件上做
3. **filled 孪生按 filled 族的同名条目判定**，不再用 `-filled` 后缀
4. `icons.manifest.ts` 只对**确有孪生**的条目置 `filled: true`（当前为 `stateVerified` / `storage` 两条，实测均有孪生）；`localModel` 用的 `cpu` 无 filled 孪生，据实去掉该标记，active 态走主色 / stroke 兜底

### 二、`offline-guard.mjs`：改到真实收敛点

1. 一律用 `createRequire(import.meta.url)` 取 **CJS 导出对象**（实测各属性 `writable=true`），不再用只读的 ESM 命名空间
2. 主拦截点选 **`net.Socket.prototype.connect`**（真正的收敛点，CJS/ESM 消费者通吃），辅以 `net.connect` / `createConnection` / `tls.connect` / `dns.lookup` / `dns.promises.lookup` / `http(s).request|get` 导出层补丁
3. `globalThis.fetch` 单独补（undici 绕过 `Socket.prototype`）
4. 补丁安装失败**记入 `patchFailures` 并让退出判定为 `[FAIL]`**——装不上守卫就不能声称 AC-01 成立，不许静默降级
5. `hostFromConnectArgs()` 覆盖三种调用形态 `({host}, cb)` / `(port, host, cb)` / `(path, cb)`，以及 `net.connect` 内部把规范化参数**数组**转交 `socket.connect` 的形态

## Consequences

**正面**
- `check:icons` 从「26 处假红 + 无条件假告警」变为「62 个图标名全解析、0 告警」，且红灯可信
- `test:offline` 从「一装就崩」变为真正跑完并给出 `[PASS] offline: 出站请求 0 次 / 回环 2 次`
- 守卫拦截能力有实测证据：5 类离站尝试（`net.connect` / 带 host 对象 / `createConnection` / `fetch` / `http.get`）全部拦截；`127.0.0.1` / `localhost` / 环回 HTTP 往返（`body=ok`）全部放行

**负面**
- 守卫依赖 `Socket.prototype` 这一内部收敛点；Node 若改内部实现需重新实测（已在文件头写明「勿凭直觉改动」与验证方法）
- `check-icons.mjs` 对目录布局做了「filled 目录段或 -filled 后缀」的假设，换图标包需复核

## 验证证据

```
[PASS] icons: 62 个图标名全部解析成功（源 5130 枚描边 SVG + 1054 枚 filled 孪生）
[PASS] offline: 出站请求 0 次 / 回环 2 次
```
