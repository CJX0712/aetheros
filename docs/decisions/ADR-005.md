# ADR-005: MCP 集成方式（官方 SDK v2 拆包，双向）

## Status: Accepted (2026-09-19)

## Background

aetheros 必须同时扮演两种角色：
- **MCP client** —— 连接外部 MCP server，把工具接进 ReAct 循环（F6）
- **MCP server** —— 把 aetheros 自身能力（检索、证据校验、技能）暴露给 Claude Desktop 等宿主

候选：
- **官方 SDK v2 拆包**（`@modelcontextprotocol/server` / `@modelcontextprotocol/client` 2.0.0，2026-07-27，实现 2026-07-28 spec）
- v1 单体包 `@modelcontextprotocol/sdk` 1.30.0（仍在维护，但为旧线）
- 自研 JSON-RPC

## Decision

**采用官方 SDK v2 拆包，同进程同时安装 server 与 client 两侧。**

- v2 是稳定发布线，v1.x 在 v2 发布后仅再获至少 6 个月的 bugfix / 安全更新
- v2 通过官方一致性测试套件（client 与 server 双向），tasks 套件因该能力在 2026-07-28 中移至扩展而暂未覆盖
- 工具 schema 走 **Standard Schema**：Zod v4 / ArkType 直接可用，Valibot 需 `@valibot/to-json-schema`

包职责（官方共 9 个公开包）：
- `@modelcontextprotocol/server` —— 暴露 tools / resources / prompts
- `@modelcontextprotocol/client` —— 连接 server 并调用
- `@modelcontextprotocol/node` —— Node http 适配器（薄层）
- `@modelcontextprotocol/core` —— 原始 Zod wire schema（仅处理裸 JSON-RPC 时用）
- `server-legacy` / `codemod` —— **仅供 v1 迁移，新项目不用**

## Consequences

**正面**
- 协议一致性由官方测试套件背书
- 同进程双向，无需进程间桥接
- Standard Schema 解耦了 schema 库选择

**负面**
- v2 为较新发布线，第三方 server 生态迁移尚未完成，可能遇到 v1-only server
- 需注意 inspector v2 要求 Node ≥ 22.19.0

## 关联硬约束

- **`stdio` 必须走子路径显式 import**：`import { StdioClientTransport } from '@modelcontextprotocol/client/stdio'`。包根入口是运行时中立的（不触碰 `node:child_process`），导入 `/stdio` 才是显式选择进程运行时
- **TypeScript ≥ 6.0 需 `compilerOptions.types = ["node"]`** —— 已发布的 `.d.mts` 引用了 `Buffer`
- F6 的 token 预算护栏在 `@aetheros/mcp` 层实现，不属于 SDK 职责
