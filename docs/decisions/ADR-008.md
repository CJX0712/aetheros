# ADR-008: 分层架构与文件组织硬约束

## Status: Accepted (2026-09-19)

## Background

生成式代码最常见的结构性烂账不是某行写错，而是把所有东西堆进一两个大文件——路由、业务逻辑、SQL、工具函数全塞进 `index.ts`，改一处牵全身，测不动也读不懂。

SPEC §4 已锁定分层：**`api/` → `services/` → `repositories/` → `infra/`**，`domain/` 为纯算法无 IO。

本 ADR 把该分层落地为可执行的目录与文件约束。

## Decision

### 分层依赖（只向下）

```
api/          命令 / 路由 / MCP handler —— 只做：参数校验(Zod) → 调 service → 组装响应
   ↓
services/     业务编排 · 事务 · 规则 —— 抛业务异常，不返回 HTTP 响应
   ↓
repositories/ SQLite 读写与映射           domain/ 纯算法，零 IO
   ↓
infra/        llama 实例 · sqlite 连接 · OTel SDK · net 出口
schemas/      Zod，独立成文件             index.ts 只装配
```

### 依赖铁律（违反即退回）

| 允许 | 禁止 |
|---|---|
| `api → services` | `repository → service`（反向） |
| `services → repositories / domain` | `api → repository`（跨层） |
| `repositories / domain → infra` | `services → repository B`（跨模块直连，应调 service B） |
| — | `services` import `req` / `res` |
| — | `domain` 触碰任何 IO |

跨模块协作走对方 **service 接口**，不直连对方 repository。

### 文件组织硬规则（出现即不合格）

| # | 规则 | 不合格表现 |
|---|---|---|
| 1 | 单一职责：一文件一主职责、一主导出 | 路由+逻辑+SQL+工具同文件 |
| 2 | **单文件 ≤ 300 行**（不含空行注释） | `index.ts` 800 行 |
| 3 | 按资源分包 | 所有 controller 堆进一个文件 |
| 4 | **入口只装配**，< 100 行，零业务 | 入口里写业务实现 |
| 5 | 业务逻辑不进路由处理器 | `router.post` 回调里 50 行业务 |
| 6 | `utils/` 只放纯函数 | 把业务流放进 utils |
| 7 | 类型 / Schema 独立成文件 | Zod schema 与业务同文件 |

> 300 行是硬上限不是目标。一个 service 超过 200 行就该警惕——大概率是把别人的活干进来了。

### 门禁命令

```bash
# 超 300 行即不合格
find packages -name '*.ts' | xargs wc -l | sort -rn | awk '$1>300 && $2!="total"{print "OVER:",$0}'
# 入口行数
wc -l packages/*/src/index.ts
```

脚本内路径一律写成 `C:/...` 形式 —— 本机 PortableGit bash 无 `/c` 挂载，传给 Windows 程序的 `/c/Users/...` 会被当成 `C:\c\...`。

### 包清单

| 包 | 职责 |
|---|---|
| `@aetheros/core` | 事件总线、配置、错误分类、Feature Flag、**`net` 出口收口** |
| `@aetheros/runtime` | ReAct 循环、工具注册表、durable 检查点 |
| `@aetheros/rag` | 索引 / 检索 / 三路融合 / 证据锚点 |
| `@aetheros/gate` | Evidence Gate（默认 strict） |
| `@aetheros/evolve` | 技能蒸馏、对照组、`.skill.json` |
| `@aetheros/aurora` | 推理 provider、线程与画像 |
| `@aetheros/mcp` | MCP 双向桥、token 预算护栏 |
| `@aetheros/telemetry` | OTel setup + SQLite exporter + 哈希链 |
| `@aetheros/ui` | `AppIcon` / `icons.manifest` / token 引用层 |
| `@aetheros/cli` | `agentos` 命令入口（只装配） |

## Consequences

**正面**
- `domain/` 纯算法零 IO，单测无需 mock，RRF / 哈希链 / 线程估算可直接验证
- 分层边界使并行开发不互相踩
- 门禁命令可机检，不依赖人工评审

**负面**
- 严格分层带来更多小文件与间接层，初期写作成本略高
- 300 行上限在复杂编排场景可能需拆得较碎，需靠命名与目录组织维持可读性
