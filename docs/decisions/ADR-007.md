# ADR-007: 测试框架与单文件 HTML 无头自检

## Status: Accepted (2026-09-19)

## Background

两个测试需求：
1. 主工程（TypeScript / Node）需要单元测试、覆盖率与 CI 门禁
2. **单文件 HTML 演示引擎要求"Node 无头自检全绿"** —— 但它是零依赖单文件，不能引入测试框架

难点在于第 2 条：若把演示引擎的算法在 Node 测试里**重写一遍**，两份实现必然漂移，测试就失去意义。

候选（主工程）：
- **Vitest 5.0.1**（2026-09-15，releasealert）
- `node:test`（Node 内建）
- Jest

## Decision

**主工程用 Vitest 5.0.1。** 与 Vite 生态同源，ESM / TypeScript 开箱支持，覆盖率与 UI 齐备；Jest 的 ESM 配置成本高，`node:test` 缺覆盖率与并发控制。

**单文件 HTML 无头自检采用「抽取执行」而非「重写实现」：**

```
apps/demo/index.html
  └─ <script id="aos-engine"> … 纯算法引擎（RRF / BM25 / 区间高亮 / ReAct 状态机）…
                                    ↑ 浏览器执行
scripts/verify-demo.mjs
  └─ node:fs 读 HTML → 按 id 抽取该 script 块 → node:vm 执行 → 跑断言
                                    ↑ Node 执行
```

同一份代码，两处运行，零重复实现。

### 演示边界（锁定）
- **演示**：RRF 融合可视化（k 可调）、证据链字符区间高亮与溯源、trace 火焰图回放、ReAct 状态机、技能包浏览
- **不演示**：任何模型推理、GGUF 加载、权重下载、真实检索 —— 全部走内置 fixture
- **零依赖**：vanilla JS + 内联 CSS + Tabler SVG path 内联（构建期生成），无 CDN / WASM / fetch
- **字体退化为系统栈**（system-ui / PingFang SC / Microsoft YaHei），不 base64 内嵌 webfont —— 数百 KB 换取一个在无网场景下无意义的 `font-display: swap`，不划算

## Consequences

**正面**
- 演示引擎的算法与 Node 断言共用一份源码，杜绝实现漂移
- 零依赖保证可被机器验证（`node scripts/verify-demo.mjs` 全绿）
- Vitest 与构建链路（tsdown / Vite）同源，配置复用

**负面**
- `node:vm` 执行要求引擎块**不得**引用 DOM API —— 引擎必须是纯函数，DOM 渲染层单独隔离
- 引擎块内不得使用 ESM `import`，需写成 IIFE 或挂全局对象

## 关联硬约束

- 引擎块标记为 `<script id="aos-engine">`，抽取逻辑依赖该 id，改动需同步 `verify-demo.mjs`
- 演示引擎为 P1 同期发布物，**不进 MVP 验收门禁**（QA 的 P0 门禁只作用于 `@aetheros/core` 与 `@aetheros/cli`）
