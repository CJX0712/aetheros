# ADR-013: 字体 vendored 与授权合规

## Status: Accepted (2026-09-19)

## Background

产品卖点是「本地优先 / 零云端」。任何 `fonts.googleapis.com` 请求都会自打脸，且离线不可用。设计侧据此要求字体 vendored。

**授权风险（本 ADR 的起因）**：设计侧初版提议 Switzer，并假定其为 OFL。经核查 **Switzer 实为 ITF Free Font License（Closed Source）—— 禁修改、禁再分发**。而 SPEC §4 要求 vendored 至 `assets/fonts/` 并做子集化，这两条行为在 ITF 下**均属违规**。SPEC 变更记录已据此将正文字体改为 Geist（OFL 1.1）。

这条是架构侧主动拦下的发布前合规事故。

## Decision

**字体全部 vendored 至 `assets/fonts/`，禁止 CDN。**

| 用途 | 字体 | 授权 | 处理 |
|---|---|---|---|
| 正文 | **Geist** | **OFL 1.1** | woff2，子集化 Latin + Latin-Ext |
| 等宽 | **Commit Mono** | **OFL 1.1** | woff2，承担代码 / ID / 哈希 / 时间戳 / 全部数字 |

**CJK 不 vendored**，走系统栈：
- `--font-sans`：Geist → system-ui → PingFang SC → Microsoft YaHei → Noto Sans CJK SC
- `--font-mono`：Commit Mono → Sarasa Mono SC → Cascadia Mono → Consolas

理由：全量 CJK 字体是 10–20 MB 量级。本地优先 = 无 CDN，不等于必须内嵌 20 MB。另提供 `agentos fonts install-cjk` 供需要像素一致的用户离线补更纱黑体。

**单文件 HTML 演示引擎不使用 webfont**，退化为系统栈。base64 内嵌会到数百 KB，而 `font-display: swap` 在无网场景下没有意义——swap 期间用户看到的就是系统字体。

## 硬约束

1. **每个字体文件必须随附 LICENSE** 于 `assets/fonts/`，**CI 校验缺失即红灯**
2. **禁止 CDN / 禁止运行时下载字体**
3. 正文字体栈必须显式列出 CJK 回退，不得只写 Latin 字体名
4. 全部时间 / 数值强制 mono + `tabular-nums`

## Consequences

**正面**
- 离线可用，与"零云端"定位一致
- OFL 1.1 明确允许 embed / modify / redistribute，子集化合规
- 系统 CJK 栈避免 10–20 MB 体积

**负面**
- 不同 OS 上 CJK 渲染存在细微差异（PingFang / 微软雅黑字形不同）
- 字体子集化需构建步骤
- 每新增字体都要走一次授权核查

## 流程约束

**任何新增字体必须先行核查授权文本**，不得假定为 OFL。核查项：
- 是否允许 **embedding**
- 是否允许 **modification**（子集化属修改）
- 是否允许 **redistribution**
- 是否要求随附授权文件

已确认违规的字体（拉黑）：**Switzer**（ITF Free Font License，Closed Source）。
