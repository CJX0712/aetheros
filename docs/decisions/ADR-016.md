# ADR-016: 设计 token 分层引用门禁

## Status: Accepted (2026-09-19)

## Background

设计系统采用 W3C DTCG 三层 token：
- **primitive** —— 原始色值 / 数值，如 `#3CCFC1`
- **semantic** —— 语义命名，不按色相，如 `--aos-accent`
- **component** —— 组件级绑定

真源：`docs/design/design-tokens.json` + `design-tokens.css`。CSS 前缀 **`--aos-`**（非 `--ag-`）。

**风险**：三层分层若只写在文档里，赶工时一定会被穿透——组件直接引用 primitive 色值，语义层形同虚设。届时主题切换、对比度修复、暗色模式都要逐个组件改。

## Decision

**组件代码只允许引用 semantic / component 两层。直接引用 primitive 层视为违规，由门禁拦截。**

1. 组件代码中出现 `var(--aos-<primitive>)` 或裸色值（hex / rgb）→ 违规
2. 由 **stylelint 自定义规则**拦截，CI 门禁
3. 允许引用 primitive 的唯一位置：`design-tokens.css` 内部（semantic 层的定义处）

### 配套硬规则

**对比度**：青底按钮文字必须使用 `--aos-accent-on`（`#04201D`）。白字压 `#3CCFC1` 仅约 2.2:1，不达标 —— 写入 lint 规则。

**两条颜色语义规则**（全项目强制）：
1. **The Trace Is Cyan Rule** —— 青色只出现在 trace / 证据 / 来源相关界面，**绝不用于营销按钮与 CTA**
2. **Amber Means Unverified Rule** —— 琥珀只用于标注「证据链不完整的断言」，不作通用 warning 色

**状态语义五态互斥**（SPEC §8.1）：`verified` / `unverified` / `refused` / `failed` / `error`。红色只留给 failed / error；**refused 是产品的正确工作结果，不得做成红色错误页**。

## Consequences

**正面**
- 主题切换 / 对比度修复只需改 semantic 层，组件零改动
- 两条颜色规则把产品承诺直接编码进视觉语言
- 机器门禁替代人工评审

**负面**
- 新增组件时需先确认 semantic 层是否已有对应 token，否则要回头补 token（有意为之的成本）
- stylelint 自定义规则需维护

## 关联约束

- 圆角 sm4 / md6 / lg8 / pill999，**全站 ≤ 8px**
- 间距 4px 网格
- **hairline-first**：`elev-ring 0 0 0 1px border`，`elev-raised` 仅浮层；**零卡片阴影、零玻璃拟态**
- 动效 80 / 150 / 200 / 320ms，`cubic-bezier(0.2, 0, 0, 1)`，只动 transform / opacity，**禁止弹跳缓动**
