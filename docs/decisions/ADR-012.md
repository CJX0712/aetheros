# ADR-012: 自进化回归基线稳定性

## Status: Accepted (2026-09-19)

## Background

evolver 的自进化层（F7）要做三件事：从 run 蒸馏 skill、跑对照组基准、通过后固化为 `.skill.json`。

问题在于：**LLM 输出不确定**。若对照组基线本身会漂移，就无法判断"新版本变好了"还是"只是采样不同"——回归测试失去意义，自进化会随机采纳或随机丢弃。

## Decision

**对照组基准必须满足三项条件，缺一不可：**

1. **`temperature = 0`**（greedy 解码）
2. **固定 seed** —— 写入 `skill_versions.baseline_seed`，每次对照复用同一值
3. **多次采样投票** —— 单次结果不采纳，取多数的稳定结论

技能包格式：
- 目录 + `.skill.json`（Zod 校验，不信任手写内容）
- 用例集随包携带
- 版本血缘：`skill_versions.parent_id` 指向上一版，支持 diff 与回滚

### 决策规则
- 回归通过（`skill_runs.passed = 1`）→ 采纳，写新版本行
- 回归劣化 → 丢弃，并记入 pitfall

## Consequences

**正面**
- 基线稳定，回归判定可信
- 固定 seed + temperature=0 使结果在相同环境下可复现
- Zod 校验的 manifest 使技能包可移植、可审计

**负面**
- `temperature = 0` 牺牲多样性，蒸馏出的 skill 可能偏保守
- 多次采样增加基准耗时（可配置为 3 次）
- 纯 CPU 上跑对照组成本不低，需限制基准集规模

## 关联硬约束

- 蒸馏产出的 `.skill.json` 必须过 Zod schema，禁止直接落库未校验内容
- 每次回归写 `skill_runs`，含逐条断言明细（`detail` 字段），便于追溯"为什么被拒"
- 与 SPEC §3 一致：**不做模型训练 / RL 微调**（需 GPU，与纯 CPU 定位冲突），自进化完全走文本化技能包
